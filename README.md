# TechNova Knowledge Assistant

Корпоративный AI-ассистент, который отвечает на вопросы сотрудников по внутренней базе знаний: политикам, регламентам, справочникам и инструкциям. Проект демонстрирует полный RAG-цикл (Retrieval-Augmented Generation) на локальных моделях: документы превращаются в векторный индекс, по вопросу находятся релевантные фрагменты, и языковая модель формирует ответ только на их основе.

База знаний наполнена документами вымышленной компании **TechNova** (ООО «ТехНова»): 41 документ в 11 тематических разделах, около 680 смысловых фрагментов. Компания и её правила придуманы специально для демонстрации — реальных требований и персональных данных в корпусе нет.

---

## Для чего нужен проект

Проект показывает, как из обычных офисных документов собрать работающего корпоративного ассистента:

- **Быстрый поиск ответа.** Сотрудник не листает десятки политик, а спрашивает: «Какой SLA у P1 для клиента Premium?» — и получает ответ со ссылкой на источник.
- **Ответы с опорой на документы.** Модель не придумывает факты: она видит только найденные фрагменты и обязана честно сказать, если информации нет.
- **Локальный контур.** Эмбеддинги и генерация работают через Ollama на вашей машине, без облачных API и передачи данных наружу.
- **Готовый сценарий замены базы.** Корпус можно целиком заменить своими документами — код менять не нужно, если вы остаётесь в формате DOCX.

Типовые сценарии использования: демонстрация RAG на защите проекта, прототип внутренней справочной, стенд для проверки качества поиска и промптов.

## Как это работает

```
DOCX  →  извлечение текста  →  метаданные  →  нарезка на чанки  →  эмбеддинги  →  ChromaDB
                                                                                  (индекс)

Вопрос  →  эмбеддинг вопроса  →  поиск top-3 фрагментов  →  промпт с контекстом
                                                              ↓
                                        qwen3:1.7b (Ollama)  →  ответ + источники
```

**Индексация (офлайн, выполняется вручную).**
Скрипт обходит `data/documents` рекурсивно, читает каждый `.docx`, присваивает чанкам метаданные и режет текст на фрагменты по 500 символов с перекрытием 100. Каждый фрагмент превращается в вектор моделью `bge-m3` и сохраняется в локальную коллекцию ChromaDB `technova_corporate_kb`.

**Ответ на вопрос (онлайн).**
Flask принимает вопрос, тем же эмбеддингом переводит его в вектор и ищет 3 ближайших фрагмента. Они подставляются в системный промпт: «отвечай только по контексту, не выдумывай цифры, если ответа нет — скажи об этом». Ответ формирует `qwen3:1.7b` с низкой температурой (0.1), а интерфейс показывает использованные документы.

**Из чего складываются метаданные.**
- `document_id` — первый код вида `TN-001` в тексте документа (если кода нет — имя файла).
- `department` — имя родительской папки без префикса до первого `_` (`05_Finance` → `Finance`).
- `document_title` — имя файла без расширения, подчёркивания заменены пробелами.

Эти поля видны в источниках ответа и помогают ориентироваться в выдаче.

**Почему документы написаны короткими разделами.**
В контекст попадают только 3 фрагмента по 500 символов. Поэтому каждый раздел политики самодостаточен: содержит конкретные сроки, пороги, роли и контакты. Это заметно повышает шанс, что модель получит полный ответ, а не обрывок фразы.

## Быстрый старт

### 1. Требования

- Python 3.11+
- [Ollama](https://ollama.com) — локальный сервер моделей
- Модели: `bge-m3` (эмбеддинги) и `qwen3:1.7b` (генерация)

### 2. Установка

```bash
cd technova

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

ollama pull bge-m3
ollama pull qwen3:1.7b
```

Убедитесь, что Ollama запущен и отвечает на `http://localhost:11434`:

```bash
ollama list
```

### 3. Индексация документов

```bash
.venv/bin/python index_documents.py
```

В выводе будет `documents_loaded`, `chunks_created` и `chunks_indexed`. Индексация выполняется один раз (и повторно — после изменения документов).

### 4. Запуск приложения

```bash
.venv/bin/python run.py
```

Откройте <http://127.0.0.1:5000> — в интерфейсе можно задать вопрос и увидеть источники ответа.

Проверка работоспособности:

```bash
curl http://127.0.0.1:5000/health
```

> Если порт 5000 занят (на macOS его часто использует AirPlay Receiver), отключите AirPlay Receiver в системных настройках или измените `port` в `run.py`.

## Как добавить свою базу знаний

Код проекта менять не нужно, если ваши документы — это `.docx`. Достаточно подготовить файлы, положить их в `data/documents` и переиндексировать.

### Шаг 1. Подготовьте документы

- Формат — **DOCX** (Word или экспорт из Google Docs). Именно `.docx` ищет индексатор.
- Один документ = одна тема. Не складывайте всю компанию в один файл.
- Текст должен быть настоящим текстом, а не картинкой: сканы без текстового слоя не индексируются.
- Таблицы лучше заменить списками или простыми таблицами без объединённых ячеек — при извлечении они читаются построчно.
- Уберите колонтитулы с дублирующимся текстом, если они не несут смысла: они могут попадать во фрагменты.

### Шаг 2. Разложите по папкам

Создайте папку внутри `data/documents`. Префикс с номером задаёт порядок и необязателен, но удобен:

```
data/documents/
├── 01_HR/
├── 02_Engineering/
├── ...
└── 12_My_Domain/
    └── KB-001_My_Policy.docx
```

Имя папки после первого `_` становится названием подразделения в метаданных. Например, `12_My_Domain` → `My Domain`.

### Шаг 3. Задайте код и имя файла

- В самом начале документа укажите уникальный код, например `KB-001` или `TN-042`. Первый код такого вида становится `document_id`.
- Назовите файл так, чтобы из имени было понятно содержимое: `KB-001_My_Policy.docx`. Из имени формируется `document_title`.

Если кода в тексте нет, идентификатором станет имя файла — это работает, но выглядит менее аккуратно в источниках.

### Шаг 4. Напишите документ так, чтобы его находил поиск

Это главное условие хорошего качества ответов:

- **Короткие разделы.** Один раздел — одна мысль и 2–4 абзаца. Не делайте простыни на несколько экранов.
- **Конкретика.** Пишите числа, сроки, пороги, роли и адреса: «первый ответ — 30 минут», а не «быстро реагируем».
- **Самодостаточность.** Раздел должен отвечать на вопрос без соседних разделов: «CFO утверждает расходы от 300 000 до 1 000 000 ₽».
- **Ключевые факты в начале.** Краткая выжимка в первых абзацах повышает шанс попадания в top-3.
- **Явные термины.** Используйте слова, которыми сотрудники реально задают вопрос: «отпуск», «закупка», «инцидент», «доступ к production».
- **Перекрёстные ссылки.** Указывайте коды смежных документов — это помогает задавать многошаговые вопросы.

### Шаг 5. Переиндексируйте

Если вы **добавляете** новые документы:

```bash
.venv/bin/python index_documents.py
```

Если вы **заменяете или удаляете** документы, сначала очистите коллекцию. Индексатор только добавляет фрагменты и не удаляет старые, поэтому без очистки в базе останутся устаревшие куски (и дубли).

```bash
# Вариант 1: удалить каталог индекса (при остановленном приложении)
rm -rf chroma_corporate_db

# Вариант 2: удалить только коллекцию
.venv/bin/python - <<'PY'
import chromadb

client = chromadb.PersistentClient(path="./chroma_corporate_db")
client.delete_collection("technova_corporate_kb")
print("collection deleted")
PY

.venv/bin/python index_documents.py
```

### Шаг 6. Проверьте результат

Задайте 5–10 вопросов, ответы на которые точно есть в ваших документах, и посмотрите на блок источников. Если нужный файл не находится:

- сделайте раздел короче и конкретнее;
- добавьте ключевые слова из вопроса в текст;
- проверьте, что документ действительно сохранился как `.docx` и попал в `data/documents`;
- убедитесь, что коллекция была очищена при замене корпуса.

### Что делать с PDF и TXT

На уровне загрузчика проект умеет читать PDF и TXT, но индексатор обходит только `*.docx`. Чтобы добавить другие форматы, потребуется изменить код индексации — это уже не «только данные». Самый простой путь без правок кода: конвертировать документы в DOCX.

## API

Приложение отдаёт простой JSON API.

**`GET /health`** — проверка доступности:

```json
{ "status": "healthy", "application": "TechNova Knowledge Assistant" }
```

**`POST /api/chat`** — вопрос по базе знаний:

```bash
curl -s http://127.0.0.1:5000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"question": "Кто утверждает закупку на 700 000 рублей?"}'
```

Ответ:

```json
{
  "question": "Кто утверждает закупку на 700 000 рублей?",
  "answer": "Закупку на 700 000 ₽ утверждает CFO...",
  "sources": [
    {
      "document_id": "TN-013",
      "department": "Finance",
      "document_title": "Tn 013 Budget Planning",
      "source_file": "TN-013_Budget_Planning.docx"
    }
  ]
}
```

Если вопрос пустой — `400`. Если RAG-конвейер упал (например, Ollama недоступен) — `500` с просьбой проверить сервисы.

## Примеры вопросов для демонстрации

**Простые факты**
- Сколько дней отпуска и какие дополнительные дни положены?
- Какой SLA у P1 для клиента Premium?
- Сколько стоит TechNova Flow Business?

**Согласования и пороги**
- Кто утверждает закупку на 700 000 ₽ и сколько нужно коммерческих предложений?
- Кто подписывает финансовый договор на 3 млн ₽?

- Что делать при потере корпоративного ноутбука?

- Что делать при утечке API-ключа?

**Многошаговые вопросы**
- Можно ли работать из-за границы 20 дней и какие согласования нужны?
- Что происходит с доступами при увольнении и за сколько часов их отзывают?
- Какой RTO у TechNova Flow и как часто тестируют восстановление?

## Настройки

Основные параметры заданы в коде RAG-модуля:

| Параметр | Значение | Где меняется |
|---|---|---|
| Модель эмбеддингов | `bge-m3` | модуль эмбеддингов |
| Модель генерации | `qwen3:1.7b`, temperature `0.1` | модуль генерации |
| Ollama | `http://localhost:11434` | модуль эмбеддингов |
| Коллекция ChromaDB | `technova_corporate_kb` | модуль векторного хранилища |
| Размер чанка / перекрытие | 500 / 100 символов | модуль нарезки |
| Количество фрагментов в контексте | 3 | маршрут `/api/chat` и слой поиска |
| Порт приложения | 5000 | `run.py` |

Если меняете модель эмбеддингов, обязательно переиндексируйте корпус: размерность и семантика векторов должны совпадать.

## Ограничения

- **Демонстрационные данные.** TechNova — вымышленная компания. Документы нельзя использовать как реальные политики.
- **Маленькая модель.** `qwen3:1.7b` быстрая и локальная, но может ошибаться в формулировках и пропускать детали. Для продакшена нужна модель крупнее и оценка качества.
- **Только 3 фрагмента.** Контекст ограничен, поэтому сложный вопрос может требовать уточнения. Увеличение `k` повышает полноту, но и расход контекста.
- **Нет гибридного поиска и реранкера.** Используется только векторное сходство; точные коды и аббревиатуры могут находиться хуже.
- **Нет разграничения доступа.** Все документы в одной коллекции; ассистент не учитывает роли и уровни конфиденциальности. Не загружайте в демо реальные секреты и персональные данные.
- **Индексация не инкрементальная по смыслу.** Повторный запуск добавляет фрагменты; при замене корпуса очищайте коллекцию.
- **Синхронный Flask.** Подходит для демо и небольшой нагрузки, но не для промышленного многопользовательского режима.
